# ADR-014: 記録から「また記録する」（同じ料理を別の日に新しく記録する入口）で確定した決定

- ステータス: 承認
- 日付: 2026-09-27

## コンテキスト

requirements.md 機能要件 19「記録からまた記録する」を実装する（ユーザ指示 2026-09-27: 投稿から同じ食べ物の別の日も投稿できるように）。

同じ料理を前回の内容ごと新しく記録する道は、要件 8 のサジェスト（[ADR-005](005-meal-suggestions.md)）だけだった。入口は記録フォームの側にあり、「まず記録フォームを開き、札の中から探す」順になる。札は料理名ごとの直近 1 件を新しい順に 20 枚までなので、しばらく作っていなかった料理は札に無い — 検索で見つけた記録から記録しようとすると、料理名・タグ・リンクを打ち直すことになる。

製品意図の 2 つ目「次に食べるもののアイディアにつなげる」で、「また作った」と気づく場面は壁を眺めているとき（♥ で絞った壁、検索で出した記録の詳細）にある。そこから記録に入れる口が要る。

決めるのは 4 つ — ①どこに置くか、②何を引き継ぐか、③記録フォームの書きかけとの関係、④詳細から開くときの dialog の受け渡し。migration も API 変更も無い（記録フォームの初期値が変わるだけ）。

## 決定

### 1. 記録の詳細と「くわしく」の行に「また記録する」を置く

記録に触れる場は 2 つ（[ADR-011](011-meal-detail.md) §1: 壁からは詳細が唯一の入口、くわしくの行は既に全部見えている場）で、どちらにも同じ操作の並び（またたべたい / 編集 / 削除）がある。そこに「また記録する」を足す。詳細では左に ♥ またたべたい と並べる — 左は「次の献立」の側、右の 編集 / 削除 はこの記録を直す・消す側。

ラベルは「また記録する」。記録の動詞（「たべたものを記録する」「記録する」）に「また」を付けたもので、♥「またたべたい」の隣で「またたべた（ので記録する）」と読める。読み上げ名は他と同じく `また記録する（肉じゃが）`。

### 2. 引き継ぐのはサジェストと同じ料理の属性。日付は今日、写真は引き継がない

引き継ぐのは 料理名 / リンク 2 種（本数ぶん全部）/ 作り方メモ / タグ で、ADR-005 §5 と同じ線。食べた日・タイミング・ひとことメモ・作った人（[ADR-012](012-meal-cooks.md) §5）・♥ は**その回のもの**なので引き継がない。写真も引き継がない — 前の写真が今回の記録に付くのは事実として誤り（ADR-005 §5）。元の記録は何も動かない（編集ではなく複製 + 新規投稿 — [ADR-008](008-meal-edit.md) が残した「別の機能」そのもの）。

実装は `carryOverFrom(meal): MealCarryOver`（記録から属性を取り出す純粋関数）と、サジェストの札が使っていた `applySuggestion` を `applyCarryOver(form, carry)` に広げたもの。`MealSuggestion` は `MealCarryOver` の形を含むので、札からも記録からも同じ関数で引き継ぐ（引き継ぎの規則が 2 つに割れない）。

### 3. 記録フォームの書きかけには、札を押したのと同じように上書きする

記録フォームは閉じても入力を捨てない（requirements 14）。「また記録する」はサジェストの札を押したのと同じ引き継ぎとして扱い、料理の属性だけを上書きして、日付・タイミング・ひとことメモ・作った人・選択中の写真はそのまま残す（ADR-005 §6「選択中の写真は同じ state に触らない」）。新しい依頼かどうかは props の参照の同一性で見分け（押すたびに新しいオブジェクト）、閉じて開き直しても引き継ぎ直さない。

知らせは既存の `role="status"` の行で、どの記録から来たかを日付で示す: 「肉じゃが」（2026年9月2日(火) の記録）の内容を引き継ぎました。日付とひとことメモは今回の分をどうぞ。

### 4. 詳細から開くときは、詳細を閉じてから記録フォームを開く

modal を 2 枚重ねない（背後の詳細は inert で意味が無く、閉じる順も分かりにくい）。詳細は `useLayoutEffect` で閉じ、記録フォームは親の `useEffect` で開くので、同じ commit で「閉じる → 開く」の順が決まる。逆だと、詳細が閉じるときの焦点の戻しが、開いたばかりの記録フォームから焦点を奪う。記録フォームを閉じたあとの焦点は、詳細を開いた壁のセル（または行の「また記録する」）へ戻る。

## 影響

- migration なし・API 変更なし。`docs/adr/**` を含む PR なので auto-merge しない
- unit: `carryOverFrom`（属性だけを取り出す・kind ごとに入力順・リンクもタグも無ければ空）と `applyCarryOver` との合成（日付・タイミング・メモ・作った人は今回のまま）
- e2e（golden path）: 詳細 → また記録する → 記録フォームが引き継いで開く（引き継がないものは空のまま）→ 別の日で記録 → 2 件目がその日の見出しの下に並び、元の記録の写真は動かない → 2 件目を消す
- 据え置き: 壁（写真だけ）のセルからの直接の入口（詳細を経由する。ADR-011 §1「壁からは詳細が唯一の入口」のまま）、ふりかえりの「よく食べているもの」からの入口（ホームの検索に飛ぶ既存の導線で足りる）

## 却下した選択肢

- **詳細を開いたまま記録フォームを重ねる** — §4。modal の重なりは閉じる順が分かりにくく、焦点の戻しも崩れる
- **写真も引き継ぐ（同じ見た目だから）** — §2。前の写真が今回の記録に付くのは誤り（ADR-005 §5 と同じ）
- **ラベルを「またたべた」にする** — ♥「またたべたい」と 1 文字違いで、隣に並ぶと押し間違える。「記録する」の動詞を残した
- **日付だけ聞いて即保存する小さな dialog** — 写真もメモも付けられず、結局あとで編集することになる。記録フォームに引き継ぐ方が 1 画面で済む
- **サジェストの札を廃止してこちらに寄せる** — 札は「今日何を作ったか思い出す」入口で役割が違う。両方残し、引き継ぎの関数は 1 つにした
