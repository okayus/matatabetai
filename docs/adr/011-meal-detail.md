# ADR-011: 写真から開く「記録の詳細」（拡大表示の置き換え・送りの操作・編集の置き場）で確定した決定

- ステータス: 承認
- 日付: 2026-09-06

## コンテキスト

requirements.md 機能要件 16「記録の詳細」を実装する。

トップのタイムラインは写真だけの壁が既定になった（requirements 15 / [ADR-009](009-photo-first-home.md)）。その壁のセルをタップして開くのは**写真の拡大表示**で、中にあるのは 写真 / 料理名と日付 / 「写真を削除」 / 「閉じる」 だけだった。壁からはタグもリンクもメモも読めず、またたべたいのトグルも編集も無い — 直すには「くわしく」に切り替えて行を探すしかない。

送りの操作（← 2 / 3 →）も写真の**下**にあり、写真は最大 80dvh まで伸びるので、スマホでは画面の外にいることが多かった。画面を触って初めて「まだ他にも写真がある」と分かるのは、操作が無いのとほとんど同じ。

決めるのは 4 つ — ①拡大表示を何に置き換えるか、②送りの操作をどこに出すか、③編集をどこで行うか、④写真を消す口をどこに残すか。migration も API 変更も無い（見せ方だけ）。

## 決定

### 1. 拡大表示をやめて「記録の詳細」にする。写真からの入口はここ 1 つ

写真をタップして開く `<dialog>` に、その記録を丸ごと置く: 写真（送れる）・食べた日・タイミング・タグ・リンクカード・作り方メモ・ひとことメモ・記録した人と、**またたべたい / 編集 / 削除**。壁のセルからも、「くわしく」のカードの写真からも同じものが開く（同じ絵をタップして違うものが出ない）。

**ページ（`/meals/:id`）にはしない。** 記録フォームも拡大表示も既に `<dialog>` で、showModal なら Esc・Android の戻る・広い画面の背景タップが素で付く（`closedby="any"` + Safari 向けの fallback — modern-web-guidance の light-dismiss-a-dialog / platform-controls-dismiss-dialog）。加えて壁のスクロール位置がそのまま残る（ページにすると戻ったときの復元を自前で持つことになる）。記録ごとの URL を配る要件は無い（家族だけの閉じたスペース）。

### 2. 送る操作は写真の上に、常に出す

暗い「舞台」の上に写真を丸ごと（`object-fit: contain`）置き、その上に ①左右の ← → の丸ボタン ②右上の「2 / 3」の札 ③下の行き先の点 を重ねる。**タップして初めて出る操作は、出ていないのと同じ** — 壁から来た人が最初に知りたいのは「これで全部か、まだあるか」なので、それを写真の上で答える。点は 8 枚までのときだけ出す（多いと点が潰れて意味が消える。札は常に出る）。

送りそのものは今までどおり横スクロール + `scroll-snap`（指の慣性も端の跳ね返りもブラウザのものが一番よい）で、いま何枚目かは `scrollLeft` から数える — `scrollsnapchange` / `scroll-state` クエリはどれも Chrome だけで、この家族は iPhone と Android の両方を使う。

舞台の高さは決め打ち（`min(55dvh, 26rem)`）。縦横の混ざった写真を送っても舞台が伸び縮みしないので、下の料理名とボタンが動かない（動くと読めないし押し損ねる）。スマホでも舞台の下に料理名・タグ・ボタンが収まる高さを選んだ。

### 3. 編集は同じ dialog の中身を差し替える

「編集」を押すとシートの中身がそのまま編集フォームになる（ページも dialog も移らない）。見出しの料理名と「閉じる」は残るので、どの記録を直しているかが常に見える。

一覧（くわしく）の行のインライン編集は**残す** — そこはカードが全部見えている場で、行がその場でフォームになるのが最短（[ADR-008](008-meal-edit.md) §7）。フォームが同時に 2 つ出ないように、詳細を開くときに行の編集を畳む。同じページに 2 つ出うるので、`MealFields` の `idPrefix` を prop にして `edit-<id>-` / `detail-<id>-` に分ける（`label` の `htmlFor` が別のフォームの入力を指さないように）。

### 4. 写真を消せるのは編集の中だけ

拡大表示にあった「写真を削除」は無くす。眺めて指で送る面に、送る指のすぐ横に破壊的なボタンを置かない（ADR-009 §5「同じ機能のボタンを 2 つ置かない」の線）。編集の中の「外す」が同じ API を叩き、**足す**のも同じ場所にあるので、写真の管理は 1 か所にまとまる。副産物として「1 枚消したら詳細ごと閉じる」という据わりの悪さも消える（消したあとも開いたまま、残りを見られる）。

## 影響

- migration なし・API 変更なし・unit は増えない（純粋関数を足していない。位置の計算は既存の `clampIndex` / `snapIndex`）
- 写真のボタンの読み上げ名が「…を拡大」から「…をひらく」に変わる（行き先が変わったので）。絵だけのボタンなので名前は `aria-label` が持つ
- e2e（golden path）: 拡大表示の段を詳細に書き換える — 送り（← と札）→ 編集から写真 1 枚を外す（R2 → D1 の順で消える事実はここに移る）→ 壁のセルからも同じ詳細が開く
- 副次の修正: 編集フォームの写真タイルが正方形になっていなかった。`width` / `height` 属性は presentational hint として `height` が残り、縦横が両方決まって `aspect-ratio: 1` が効かない状態だった（写真の実寸ぶん縦に伸びる）。`block-size: auto` を足して直した
- 据え置き: 記録ごとの URL、詳細から次の記録へ送る（記録どうしのカルーセル）、写真の並べ替え

## 却下した選択肢

- **`/meals/:id` の詳細ページ** — §1。dialog なら閉じる手段が素で付き、壁のスクロール位置が残る
- **拡大表示のまま「編集」だけ足す** — 写真の下に日付もタグも出ていない場に編集だけ置いても、直す前に「何を直すのか」が読めない
- **詳細の中に「写真を削除」を残す** — §4。送る指のすぐ横に破壊的なボタンを置かない
- **← → を写真の下に置いたまま、写真の高さだけ詰める** — 送りの操作がスクロールの下に隠れる問題は残る（画面の高さは端末ごとに違う）
- **点（dots）を枚数によらず常に出す** — 多いと潰れて意味が消える。8 枚を超えたら札だけにする
- **一覧の行のタップでも詳細を開く** — 行は既に全部見えているので、同じものが二重に出るだけ
- **写真の上に料理名と日付を重ねる（インスタ風のキャプション）** — 写真の明暗によって読めなくなる。文字は舞台の外に置く
