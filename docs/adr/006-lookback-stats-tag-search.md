# ADR-006: ふりかえり（またたべたい一覧・料理名の期間集計・タグ検索 AND）で確定した決定

- ステータス: 承認
- 日付: 2026-09-02

## コンテキスト

requirements.md 機能要件 6（タグ検索 AND）・7（料理名の集計）・9（またたべたい一覧）を Phase 3 の第一弾として実装した。ADR-005 が「回数の表示」「またたべたい一覧」を意図的にここへ送っていた、その受け取りでもある。表は増やさず（migration なし）、クエリの正典は requirements「主要クエリ」。この ADR が決めるのは API の形と UI の置き場所。

## 決定

### 1. またたべたい一覧とタグ検索は一覧 API のフィルタ（新エンドポイントを作らない）

`GET /meals?tags=a&tags=b&mataTabetai=1`。どちらも「meals の部分集合」であって別リソースではなく、フィルタなら直交して合成できる（「またたべたいの中からじゃがいもで」）。tags の意味・正規化・上限 10 はサジェストと同じスキーマ（`SuggestionTagsQuery` を `TagFilterQuery` に改名して共用）。`mataTabetai` は `"1"` だけを受ける — 「絞るか絞らないか」の一択で、false を送る形を持たない。並び・LIMIT 50 は無絞り込みの一覧と同じ。

### 2. 集計は `GET /meals/stats?from&to`、表示名と最終日は「直近 1 件」から

正典の `GROUP BY name_normalized` を window 関数で書き、`row_number()` の rank = 1 行（その名前の直近 1 件）から表示名・最終日を拾う。bare column の非決定を避ける理由も形も ADR-005 §2 と同じ。並びは COUNT(\*) DESC、同数は直近が先、なお同着は name_normalized 昇順。♥ は期間内のどれかに付いていれば立てる — 要件 9「集計で前に出す」は**並び替えではなく印**で満たす（並びの正典は COUNT DESC のまま）。`from` / `to` は任意（無指定は全期間）・両端を含む・逆転は 400。上限 100 件、ページングなし（家族規模）。

### 3. UI は 1 ページ「ふりかえり」（/lookback）、開いた既定は またたべたい

nav に「ふりかえり」を足し、「記録をさがす」（scope 札: ♥ またたべたい / ぜんぶの記録 + タグ絞り込み）と「よく食べているもの」（date 入力 2 つ）を縦に置く。既定を またたべたい にすることが要件 9「一覧で前に出す」の実装。フィルタは component state に置き、URL には持たない（共有・ブックマークの要件が出てから）。またたべたい絞り込み中に ♥ を外しても行は消さない — 誤タップを戻せるようにし、消えるのは次の読み込みから。

### 4. 一覧の描画を共有コンポーネントへ

みんなの記録とふりかえりが同じ記録カード（写真・タグ・♥ トグル・削除・lightbox）を出すため、`MealList` / `TagFilter` を `src/components/` に切り出した。読み込み・並び・空文言は親の責務のまま。

## 影響

- migration なし（読みだけ）。ただしこの PR は `docs/adr/**` を含むので auto-merge しない
- e2e: golden path に「ふりかえり（既定 ♥ → ぜんぶ → タグ AND → 期間で 0 件 → 戻す）」を、boundary に stats の 404 と集約の space 隔離を追加。seed の他家族 meal に ♥ とタグを付け、「自分のスペースでは空」の検査を“実在するのに混ざらない”の意味にした
- 週 / 月のプリセット・タグクラウド・部分一致検索・集計行タップは据え置き（requirements backlog のまま）

## 却下した選択肢

- **`GET /mata-tabetai` のような専用エンドポイント** — フィルタが合成できず、一覧と同じ形をもう 1 つ増やすだけ
- **集計の並びを「♥ 先頭」にする** — 並びの正典は COUNT DESC。前に出すのは印で足りる
- **集計行タップでその料理の履歴へ** — 料理名の完全一致フィルタが要る。部分一致検索（backlog）と一緒に考える
- **フィルタ状態を URL に持つ** — 家族アプリに共有可能なフィルタ URL の要件がまだ無い。router も pathname 購読だけの最小実装のまま

## 改訂 2026-09-03 — 週 / 月のプリセットとタグクラウド（据え置き分の回収）

上で「据え置き」とした 週 / 月のプリセットとタグクラウドを実装した。Phase 3 の残りはこれで無い。

### 5. 期間は DU（プリセット + いくつ前か）で持ち、from / to は毎回導出する

ユーザーが選んだのは「今週」「先々月」であって `from` / `to` そのものではないので、選択を `StatsPeriod`（`all` / `week` / `month` / `custom`）で持ち、範囲は `periodRange(period, today)` で導出する（`src/lib/stats-period.ts`、純粋関数 + unit 15 本）。`offset` は 0 が「いま」で負が過去 — 記録は過去にしかないので `stepPeriod` は 0 を超えない。日付演算は `new Date(y, m, d + n)` に繰り上がりを任せ、月末・年またぎ・閏日を自前で数えない。週の始まりは日曜（日本のカレンダー。`Intl` の `weekInfo` は当てにしない）。`custom` の空欄は「その端を切らない」で、両端が空なら `all` と同じ問い合わせになる。

### 6. 集計 API は `/meals/stats` のまま。タグクラウドだけ同型の `GET /meals/tag-stats?from&to` を足す

プリセットは期間を組むだけなので `/meals/stats` は無改造。ただしクラウドは札の大きさに回数が要る一方、既存の `GET /tags`（サジェストの語彙）は回数を返さず期間も持たない。語彙の口に期間つき集計を混ぜると 1 つのエンドポイントが 2 つの責務を持つので、`/meals/stats` の兄弟として `GET /meals/tag-stats?from&to` を足した（`MealStatsQuery` を共用、`meal_tags ⋈ tags ⋈ meals` を `meals.space_id` と期間で絞り `GROUP BY tags.id`、多い順 → `name_normalized` 昇順、上限 40）。表示名は group by しているタグ行そのものの列なので、ADR-005 §2 の bare column 非決定は起きない。migration なし（読みだけ）。

### 7. 開いた既定は「今月」、一覧の既定は またたべたい のまま

期間 UI を入れる意味は「いまの食卓が出ること」なので、集計の既定を全期間から今月に変えた（「ぜんぶ」は 1 タップ隣）。記録が無い月は「この期間の記録はまだありません。」で、札がすぐ上にある。§3 の「一覧の既定は またたべたい」は変えない。

### 8. タグクラウドの札は「その食材の記録をさがす」の入口

札をタップすると「記録をさがす」がそのタグ 1 つの絞り込みになり、♥ の枠は外れる（クラウドから来た意図は「この食材の記録が見たい」で、またたべたい に限らない）。飛び先はページ下→上なので、section に focus を移してからスクロールする（読み上げが付いてこないため）。§3 が却下した「集計行タップでその料理の履歴へ」と違い、タグには完全一致のフィルタ（`?tags=`）が既にあるので新しいクエリが要らない。

札の大きさは回数（面積が回数に比例するよう平方根で開く）だが、**回数に差が無ければ大きさも変えない** — 1 回ずつの週で全部が最大になると、無い強弱を大きさで語ってしまう。大きさは飾りなので、回数そのものは札の中の数字と読み上げ用の「N 回つかいました」が持つ。

### 影響（改訂分）

- migration なし。`docs/adr/**` を含む PR なので auto-merge しない
- ふりかえりの構成が変わった: 「よく食べているもの」の region は「食べたもののまとめ」になり、その中の h3 2 つ（よく食べているもの / よく使ったタグ）が同じ期間を見る。golden path の集計ブロックを差し替え（既定の今月 → ← で先月は 0 件 → → で戻る → 日付指定の口 → クラウドから一覧へ）、boundary に `/meals/tag-stats` の 404 と space 隔離を追加
- 据え置きのまま: 日本語の部分一致検索、集計行タップ、フィルタ状態の URL 化
