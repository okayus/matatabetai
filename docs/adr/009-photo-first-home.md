# ADR-009: 写真ファーストのトップページ（ホームの検索・ふりかえりとの役割分担・フィルタの URL 化）で確定した決定

- ステータス: 承認
- 日付: 2026-09-05

## コンテキスト

requirements.md 機能要件 15「写真ファーストのトップページ — トップページは検索と投稿済み写真を主役にする。タイムラインの既定は『写真だけ』」の後半を実装する。前半（既定を写真だけに）は #56 で本番稼働済み。

いまのトップは「こんにちは、X さん」の h1 → 「みんなの記録」（写真の壁）→ 「スペース」一覧 → （owner でなければ）「自分のスペースを作る」の順で、検索はふりかえり（/lookback）の「記録をさがす」（♥ / ぜんぶ の札 + タグ AND）にしか無い。料理名で探す口はどこにも無く、requirements「主要クエリ」の部分一致（`name_normalized LIKE '%…%'`）は未実装。

決めるのは 3 つ — ①ホームに置く検索の中身、②ふりかえりとの役割分担、③挨拶 h1 とスペース節の置き場。migration は無い（読みだけ）。

## 決定

### 1. 検索はホーム。料理名の部分一致は一覧 API のフィルタ `?q=` として足す

ホームの写真の壁の上に `<search>` を置き、中身は **料理名のテキスト検索 + ♥ またたべたい のトグル + タグ AND**（既存の `TagFilter`）の 3 つ。どれも `GET /meals` の絞り込みで、ADR-006 §1「またたべたい一覧とタグ検索は一覧 API のフィルタ」の線に `q` を 1 つ足すだけ（`?q=&tags=&mataTabetai=1` は直交して合成できる）。

`q` はサーバーで `normalizeName`（NFKC + trim + 小文字）してから `name_normalized LIKE '%…%' ESCAPE '\'` で比べる — 保存側と同じ正規形どうしの比較なので全角英数・半角カナの揺れは吸収でき、`%` `_` `\` は `likePattern` でエスケープする（純粋関数 + unit）。かなとカナの折りたたみ・FTS5 は持たない（requirements「日本語の部分一致検索は当面 LIKE」。FTS5 は Phase 4 のまま）。並び・LIMIT 50 は無絞り込みの一覧と同じで、`q` の対象は料理名だけ（タグはタグの札で絞る。1 つの欄に 2 つの意味を持たせない）。

### 2. テキストは「さがす」で確定、札は押した瞬間に効く

テキスト検索は `<form>` の submit（Enter / スマホのキーボードの検索キー / 「さがす」）で送る。入力のたびに送る search-as-you-type は採らない — 日本語は IME の変換途中の値で `input` が飛ぶので、composition の扱いと debounce が要り、家族規模の効きに対して触る量が多い。空にしたときだけは即座に解除する（`type="search"` の × でも Backspace でも、消したのに前の結果が残るのは変）。♥ とタグの札は ADR-005 §7 と同じく押した瞬間に一覧が変わる（`aria-pressed` のボタン）。

### 3. ふりかえりは「まとめ」だけ。札と行はホームへ飛ぶ

ふりかえりの「記録をさがす」節は撤去し、記録を探す・眺めるはホームに一本化する（同じ絞り込み UI が 2 ページにあると、どちらで探すかを毎回考えさせる）。ふりかえりに残るのは「食べたもののまとめ」（期間プリセット・よく食べているもの・よく使ったタグ）で、

- タグクラウドの札 → ホームをそのタグ 1 つで絞った URL（`/?tags=…`）へ。ADR-006 §8「クラウドの札はその食材の記録をさがす入口」の飛び先がページ内スクロールからホームに変わる
- 「よく食べているもの」の料理名 → ホームを `q=` で絞った URL へ。ADR-006 §3 が「料理名の完全一致フィルタが要る」として却下した行タップは、部分一致ができたので採用する（`カレー` が `カレーうどん` も拾うのは検索欄に語が入って見えるので混乱しない）

どちらも URL への遷移なので `<a href>`（`Link`）にする（button のままだと「戻る」で戻れない）。要件 9「一覧で前に出す」は、ふりかえりの既定 ♥ 一覧（ADR-006 §3）からホームの ♥ トグルに引き継ぐ。

### 4. 絞り込みの状態は URL のクエリに持つ

`/?q=カレー&tags=鶏肉&tags=玉ねぎ&mataTabetai=1`。ADR-006 §3「フィルタ状態を URL に持たない（共有・ブックマークの要件が出てから）」を撤回する — 要件が出た: §3 のページ間の遷移に状態の受け渡しが要り、トップが検索のページになった以上、スマホの引っ張り更新（リロード）で検索が消えるのは困る。副産物として「ホーム」リンクが素の壁に戻る合図になる（URL が `/` になれば絞り込みも無い）。

パラメータ名は API と同じ `q` / `tags` / `mataTabetai`（語彙を 2 つ持たない）。解析と組み立ては純粋関数（`src/lib/meal-filter.ts`、unit で往復を固定）。札の切り替え・テキストの確定は `replaceState`（履歴を汚さない。「戻る」は前のページへ）、ふりかえりからの遷移だけ `pushState`。router には `location.search` を購読する `useSearch` を足すだけで、pathname 購読の最小実装は変えない。「写真だけ / くわしく」の見せ方は URL に持たない（絞り込みではなく描き方。既定に戻る #53 の決めのまま）。

### 5. h1 はスペース名、スペース一覧と「自分のスペースを作る」はアカウントへ

挨拶の h1 は消す（写真が主役のページで 1 行を名乗りに使わない。表示名はアカウントにある）。h1 はスペース名 — 家族のアルバムの題として壁の上に立ち、「＋ 記録する」を横に置く。「みんなの記録」の h2 は h1 に吸収する（見出しを 2 段重ねない）。

「スペース」一覧（役割・人数・設定リンク）と「自分のスペースを作る」はアカウントページへ移す。招待で入った家族には「自分のスペースを作る」フォームがホームの末尾に毎回出ていたが、これは所属の管理であって記録を眺める場に要らない。所属ゼロ（全スペースから外された）のときだけホームがアカウントへの案内を出す。

### 6. 記録したら絞り込みを既定に戻す

絞り込み中に「＋ 記録する」で記録すると、新しい記録は絞り込みに合わないことが多く、壁に出ないと「保存できたのか」が分からない。送れたら絞り込みを既定（URL を `/`）に戻して先頭に挿す — 既定なら手元の挿入がそのまま見え、絞り込み中なら URL の変化が一覧を読み直す（新しい記録は先頭にいる）。

## 影響

- migration なし（読みだけ）。`docs/adr/**` を含む PR なので auto-merge しない
- 見出しと landmark が変わる: ホームの region 名は「みんなの記録」からスペース名に、「記録をさがす」region は無くなる。e2e の golden path は ホームの検索（♥ → タグ AND → 料理名 → 解除）と ふりかえりからの遷移（札 → ホームが絞られる、行 → `q`）に書き換え、boundary に `?q=` の space 隔離を足す
- unit: `likePattern`（エスケープ）、`MealListQuery.q`（空は無指定）、`meal-filter`（URL の往復・未知のパラメータは無視・`mataTabetai` は `1` だけ）
- `PhotoGrid` の空文言は「写真のついた記録が無い」を絞り込み中にも通じる形にする（写真の無い記録は くわしく にいる）
- 据え置きのまま: FTS5 / かなカナ折りたたみ、ページング、スペース切替 UI、絞り込みの共有 UI（URL は持つが「共有する」導線は作らない）

## 却下した選択肢

- **search-as-you-type** — §2。IME と debounce の分だけ触る量が増え、家族規模では確定で足りる
- **ふりかえりの「記録をさがす」に写真だけの見方を足す**（#53 で見送った案）— 絞り込みが 2 ページに残り、役割分担が付かない。ホームに一本化した
- **`/search` の専用ページ** — トップ自体を検索のページにするのが要件 15。ページを増やすと壁と検索が離れる
- **`q` でタグも引く** — 1 つの欄に 2 つの意味を持たせない（§1）。タグは札で AND
- **フィルタを `history.state` で渡す** — リロードで消え、URL に出ないので §4 の目的（引っ張り更新・ホームで戻る）を満たさない
- **h1 を「みんなの記録」のまま残す** — スペース名を出す場所がホームから消える。アルバムの題として h1 に置いた（§5）
- **記録後も絞り込みを保つ** — 新しい記録が壁に出ないことがある（§6）
